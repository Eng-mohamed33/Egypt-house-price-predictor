# بكام؟ | Egypt House Price Predictor

Predicts the asking price of a property in Egypt from its type, location, size and description, and returns a **likely price range** instead of a single number.

Trained on ~19,000 PropertyFinder Egypt listings.

## Results

Evaluated on a held-out 20% test set. Errors are in EGP, after converting back from log prices.

| Model | MAE | Median abs. error | MAPE |
|---|---|---|---|
| Baseline (always predict the median) | 8.94M | 5.22M | 85% |
| Ridge regression | 4.72M | 2.56M | 42% |
| Random Forest (no description features) | 4.15M | 2.22M | 37% |
| **Random Forest (all features)** | **3.94M** | **2.02M** | **35%** |

The 25th to 75th percentile range from the forest's trees covers the true price about 53% of the time (it should be about 50%), so the range is reasonably calibrated.

## What I learned

- **The compound is by far the most important feature.** The exact location drives price more than size or bedroom count. Target encoding it (about 1,450 values) gave the biggest single gain.
- **Target encoding must be done out-of-fold**, after the train/test split. Otherwise a row sees its own price in its features and the scores look better than they really are.
- **Keywords from the description helped a little** (error from 37.4% to 34.9% MAPE), for example "fully finished" and installment plans.
- **MAE alone is misleading** here because a few very expensive listings dominate it, so I report relative error (MAPE) and the median error too.

## Limitations

- The data are **asking prices from listings**, not final sale prices.
- Finishing level, floor, view and exact delivery date are mostly missing, so the output is an estimate, not a valuation.
- Some listings have wrong prices (for example an apartment at 202k EGP, probably an installment or a down payment entered as the price). These produce the worst errors and come from the data, not the model.
- `description length` is a useful feature but is likely a proxy for the type of advertiser (large developers write long descriptions), not a direct cause of price.
- Compounds that were not in the training data fall back on the area average, and the app warns about it.
- The model is weaker on rare combinations (for example a 150 sqm villa in a compound where villas are usually 350+ sqm), and its range can be too narrow there. The app shows how many comparable listings exist and warns when there are few.
- The estimate can be sensitive to a single input: in one test, changing a 186 sqm apartment from 2 to 3 bathrooms moved the estimate from 12.2M to 17.7M EGP, because 2 bathrooms is unusual for that size. Check the similar-listings line as a cross-check.

## Run it locally

1. Download the dataset (Egyptian Real Estate Listings on Kaggle) and put `egypt_real_estate_listings.csv` next to the notebook.
2. Run all cells of `egypt_house_price_predictor_en.ipynb`. The last cells create `price_model.joblib` (about 69 MB).
3. Install and start the app:

```bash
pip install -r requirements.txt
python app.py
```

Then open the local URL that Gradio prints (usually http://127.0.0.1:7860).

If `egypt_real_estate_listings.csv` (or the Kaggle zip) is in the same folder, the app also orders compounds by popularity and shows **similar listings** (same type and compound, size within ±25%) next to the estimate, with a low-confidence warning when fewer than 8 exist. Without the CSV it still works, just without these extras.
